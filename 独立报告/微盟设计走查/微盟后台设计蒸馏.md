# 微盟商家后台的表单与业务页面设计

这份笔记供 ERP 前端开发者、设计者和生成页面的 AI 使用。下文的“微盟实访”描述当前账号里实际打开的界面，“ERP 建议”是据此提出的设计选择，供项目定稿时取舍。

## 1. 先决定用户在哪儿完成任务

| 用户要做的事 | 微盟实访 | ERP 建议 |
|---|---|---|
| 在列表里补一个简单对象 | 商品标签把名称和显示开关放在居中弹窗里。新增作者同样用弹窗，容纳头像、昵称和备注。新增分组与编辑分组沿用同一套字段顺序。见图 08、09、12、16。 | 字典项、岗位等小对象，若提交后自然回到原列表，可用弹窗。编辑时保留字段顺序，回显已有值。 |
| 只改一张表里的一个局部 | 质检设置新增评分项后，名称和分值直接在新行中输入，行尾有“保存、关闭”。页面底部另有整页保存。见图 48。 | 明细行的添加、撤销和整张单据的提交要能区分。若行也能独立保存，按钮应写明保存对象。 |
| 配置一个需要解释的对象 | 商品属性字段很少，却单开编辑页。属性筛选带说明和示例，属性值可逐项新增、拖动排序。创建团队同样独占一页，包含团长选择和初始团员规则。见图 02、11、15。 | 涉及子项、排序、参照或规则解释时，即便字段少，也可以用独立页。 |
| 完成横跨多个业务主题的录入 | 新建商品与编辑已有商品都提供商品信息、销售信息、支付信息、配送与服务、图文详情、其他信息六个章节。销售信息内嵌规格明细表。见图 20–22、60。 | 主子表单据用独立页。先划分单据头、明细和结算，再给长页加章节入口。 |
| 在录入中选另一个对象 | 券模板选择器留住主表单，弹层内有搜索、候选表、分页、已选数量和确定。选团长用较简单的候选表，并解释已有团长为何不出现。见图 07、15、33。 | 小枚举用下拉。选供应商、合同、来源单行等需要比对多个字段的对象用参照弹层。回到原字段显示选中对象的业务名称。 |
| 看少量关联信息 | 权益列表里的规则数量可以就地展开规则名。团队创建历史单独开只读弹窗，表里列创建状态和失败原因。见图 52、53。 | 一两条解释放在触发点旁。带时间、状态和多行记录的历史放到可独立阅读的面板。财务单据详情仍需真实样本。 |

## 2. 表单怎么排

### 录入沿一条主轴，查询允许跨列

品牌编辑页按从上到下的顺序填写类别、证件类型、名称、注册信息、有效期和附件。宽屏上仍保持单列和统一控件起点。线上交易的目标是组合查询，同一行横排多个短条件，每个条件的标签紧跟自己的控件。一个页面里也可以有两种密度，商品编辑页的普通字段纵向排，规格和价格放入横向明细表。[品牌表单](./截图/03-新增自有品牌.jpg) · [交易查询](./截图/01-线上交易.jpg) · [商品规格明细](./截图/22-销售信息.jpg)

| 实测位置 | 当时的 CSS 像素 | 设计含义 |
|---|---|---|
| 品牌名称、商标注册人、商标注册号、商标分类 | 四个文本输入的纵向起点相隔 64 px。品牌名称整行高 32 px，输入外框宽约 352 px。 | 设置标签列和常规输入宽度。宽屏多出的空间可以留白，较短的字段不必铺满整行。 |
| 品牌编辑页 | 表单行从 x=276 起，控件从 x=380 起。品牌名称的实际标签文字在控件左侧，标签与输入可独立对齐。 | 把“标签预留宽度”和“标签文字宽度”分开处理。长标签、必填标记和帮助文字都要有位置。 |
| 商品标签弹窗 | 面板宽 400 px，正文两侧各约 24 px，输入外框宽约 262 px，底部按钮 72 × 32 px。 | 两字段弹窗可采用窄版。按钮按组靠右，关闭后回原列表。 |
| 客服快捷回复弹窗 | 面板宽 540 px，关键词输入外框约 412 px；同一面板还容纳多行回复和图片上传。 | 文本和媒体需要更大阅读宽度，即使字段数量接近，也可以提升一个宽度档。 |
| 线上交易查询 | 在 2560 × 1215 CSS px 视口下，前两排输入起点纵向相差 48 px，查询和重置为 80 × 32 px。 | 查询表单可以更紧凑。只测得这一宽度，窄屏列数和断点须独立验证。 |

以上数值用于复现样例的比例。项目可以先用现有 Element Plus 尺寸和间距做样页，再决定自己的尺寸档。原始采样含原生输入框和按钮的位置，输入外框尺寸另以可见控件边界核对。

### 让字段顺序反映依赖关系

1. **决定后续分支的字段在前。** 品牌先选自有或代理。切到代理后，页面增加授权有效期、授权级数和销售授权书。分组先选一级或二级，切到二级后出现必填上级分组、分组图片和热门推荐。用户能在刚作决定的位置理解新增要求。[品牌切换前](./截图/03-新增自有品牌.jpg) · [品牌切换后](./截图/04-代理品牌联动.jpg) · [分组对照](./分组联动对照.jpg)
2. **一个业务判断占一个字段组。** 品牌有效期把起止日期和“长期有效”放在一起。优惠券把是否启用件数门槛、数量、单位“件”和适用说明放在一起，未启用时数量输入禁用。ERP 里的“指定到期日／长期有效”“按比例支付／固定金额”都可使用这种布局。[品牌有效期](./截图/03-新增自有品牌.jpg) · [多渠道券](./截图/06-多渠道券表单.jpg)
3. **同一种控件也有不同的出现方式。** 某一类对象专属的字段，微盟会在切换类别后增加；当前规则本身就需要说明的参数，会保留在原位并禁用。ERP 应按业务含义决定显隐，并在接口侧明确切换前录入值是否保留。后者属于项目需要定义的数据行为。
4. **输入旁只放会影响当前决定的说明。** 新增客户字段在“字段格式”旁说明保存后不能更改。品牌上传区就地给出材料、格式和大小要求。创建团队在初始团员选项旁说明人员归属会怎样变化。用户在决定之前就能看到结果。[客户字段](./截图/10-客户字段.jpg) · [新增品牌](./截图/03-新增自有品牌.jpg) · [创建团队](./截图/11-创建团队.jpg)
5. **根据用户要核对的结果使用预览。** 优惠券编辑旁显示券面，开屏活动旁显示移动端效果，单据设置旁显示小票样式。这些预览回答“对方会看到什么”。付款申请的右侧更值得留给来源单、可付余额或合计，是否常驻要看经办人需要同时比对什么。[券面预览](./截图/06-多渠道券表单.jpg) · [开屏活动](./截图/24-新建活动.jpg) · [小票设置](./截图/19-单据设置.jpg)

### 校验、保存和离开

在“新增标签”里输入文字、清空后按 Tab，焦点移到显示开关，名称输入框变红，下方显示“标签名称不能为空”，弹窗保持打开。新增作者把字数计数贴在昵称和备注控件旁。创建团队把最少字符要求放在名称下方。三者分别解决输入错误、剩余容量和填写前预期。[失焦校验](./截图/14-标签失焦校验.jpg) · [作者录入](./截图/12-新建作者.jpg) · [团队录入](./截图/11-创建团队.jpg)

弹窗里的“取消／确定”成组靠右。品牌与商品属性独立页在工作区底部提供整页操作。商品编辑在切到销售信息后仍能看到底部发布按钮。ERP 的“保存草稿”“提交审批”“同意付款”具有不同后果，应使用具体动作名。键盘提交、关闭后焦点回归、保存失败、重复提交、离开未保存表单等行为需要在项目里单独验收。[属性编辑](./截图/02-新增属性.jpg) · [商品编辑](./截图/21-真实商品编辑.jpg) · [切到销售信息](./截图/22-销售信息.jpg)

## 3. 列表、台账和明细怎么排

| 设计问题 | 微盟实访 | ERP 建议 |
|---|---|---|
| 查询条件属于哪一批结果？ | 交易对账从上到下是业务页签、查询区、交易总额与条数、导出、结果表。商品列表又按商品类型和售卖状态切分。 | 业务页签承载不同工作集合。筛选作用于当前集合。总额注明是按当前查询汇总还是只计已选行。 |
| 如何承载很多金额和状态？ | 线上交易有 31 个字段。表头右端的设置入口打开“可选字段／已选字段”。应付账单把应付、付款中、已付和付款金额合计列为独立口径。 | 默认优先展示本次任务要比对的金额、状态和单号。次要字段允许配置。长金额、零值、负数和空值应放进样例验证。 |
| 用户操作的是哪一层？ | 商品列表将编辑、推广等动作放在行上。商品规格表把销售价、成本价、编码、库存、单位组织到同一明细行。质检新增行另有保存。 | 区分整张单据、所选行和当前行。不同作用范围的操作放在对应区域。金额统一按项目的精度规则处理。 |
| 没有记录时还有什么可用？ | 线上交易仍显示筛选、表头、交易总额和空态；选团长仍显示搜索、列名、分页与候选资格说明。PE 版本限制页会说明所需版本。 | 区分当前筛选无结果、尚无基础资料、权限不足。前两种分别提供重置筛选或创建资料的入口，权限限制说明所需条件。 |

## 4. 选择器、导入和配置

- **依赖比较的参照对象要带表格。** 选券模板要比较名称、备注、类型和减免金额，弹层明确“已选 0 项”，可清空、取消、确定。选团长更强调候选资格。选商品类目则提供搜索、常用类目和当前路径。三者的控件和字段都要服从选择任务。[券模板](./截图/07-券模板选择器.jpg) · [人员](./截图/15-选择团长.jpg) · [类目](./截图/63-商品类目选择.jpg)
- **先选场景，再填写差异大的表单。** 新建优惠券先区分多渠道和指定渠道，新建客户分群先区分条件创建和导入创建。进入条件创建后，界面提供“满足”和“排除”两块条件区。ERP 里手工制单和从来源单生成若有不同的数据准备过程，可以用这种入口。[发放场景](./截图/05-选择发放场景.jpg) · [创建人群](./截图/34-新建自定义人群.jpg) · [条件构建器](./截图/55-人群条件构建器.jpg)
- **导入先交代格式和冲突处理。** 客服快捷回复说明覆盖或保留已有回复，接受 Excel，文件上限 3M。客户资料导入提供模板，说明手机号的唯一性，文件上限 10M。两条流程都有上传区，限制按对象分别定义。ERP 导入表头和明细时，还要明确单据与行的匹配键、部分成功如何回查。[快捷回复导入](./截图/50-导入快捷回复.jpg) · [客户资料导入](./截图/61-客户信息导入.jpg)
- **同名功能的复杂度可以差很多。** 商城标签只需名称和显示开关；CDP 的标签还要定义标签组、渠道、使用范围、可见范围和内容。组件可复用，字段模型要跟具体业务走。[商城标签](./截图/08-商品标签.jpg) · [CDP 标签](./截图/49-新建标签.jpg)

## 5. 三个 ERP 页面如何据此设计

以下是项目应用建议，可直接作为样页的设计输入。字段和状态仍以实际接口与业务约定为准。

**项目岗位。** 列表首屏展示岗位名称、编码、状态和行操作。新增与编辑共用短弹窗，按编码、名称、是否经理岗位、状态排列。默认值直接回显。若经理岗位存在唯一性限制，在对应字段说明作用范围，冲突时保留已填写内容。编辑已被引用的岗位时，在相关字段或动作旁解释限制。优先参考图 08、14、16。

**应付台账。** 常用条件放供应商、账期和付款状态，更多条件收起。结果区先显示当前查询范围内的金额汇总；表格优先并排展示应付、已付和未付，保留币种与统计口径。付款中金额是否计入未付需要业务明确。表头允许增减列，进入来源单后返回原来的筛选与行位置。优先参考图 01、17、20、62。

**付款申请。** 页首保留单号、当前状态与可执行动作。基本信息纵向组织申请组织、收款方、结算方式和日期。在明细区用“选择来源单”打开参照表，候选行显示原单号、行号、可付余额和币种。确认选择后回填明细，金额在表格中录入、就地校验并汇总。附件放在对应业务段，提交审批放在整单操作区。多币种、审批退回、回写、行级权限和金额校验属于 ERP 自身的设计工作。优先参考图 03、07、15、22、48。

## 6. 交给开发者或 AI 的页面说明

实现每个页面时，页面说明应能回答下列问题。项目技术栈沿用既有方案，布局优先用 Element Plus 表单、网格、弹窗和现有表格封装表达。

| 需要写清的内容 | 一个可执行的描述 |
|---|---|
| 从哪里进，做完回哪里 | “从岗位列表点编辑，弹窗回显选中行；关闭后仍在原列表位置。” |
| 为什么选择这个版式 | “付款申请需要同时处理单据头、来源行和金额合计，采用独立页。” |
| 哪些字段决定后续输入 | “选择从来源单生成后出现参照入口；已选来源行显示原单号和可付余额。” |
| 谁能看到或编辑，何时校验 | “填写金额离开单元格时检查格式，提交时再次核对余额；失效提示指到对应行。” |
| 操作影响哪个对象 | “移除只作用于当前明细行，保存草稿作用于整单，提交审批会改变单据状态。” |
| 哪些状态需要给设计稿 | “空表、带样例数据、条件字段展开、局部校验失败、只读、提交中、提交失败。” |

## 7. 覆盖范围与证据边界

逐项访问顶部 11 个入口与当前账号暴露的侧栏菜单。“推广”与“店铺”共用侧栏。按实际目标地址去重后为 **173 个入口**。页签按“模块、菜单、页签名”计数，记录 **327 项**，其中 **325 项核实选中**；数据权限页另有两个入口停在 PE／数据制表授权说明。选中说明导航生效，具体功能的可用性仍取决于权限、配置和数据。图册收录 **58 张截图**。

有记录的商品列表、商品编辑、分组编辑、规则浮层用于验证数据回显。当前账号中的交易、应付、客户等空列表可验证查询结构、表头和空态，其真实单据详情、审批轨迹与操作结果仍缺样本。推广商品的“添加商品”和知识库的“添加问题”尝试进入后只确认到列表。应用市场内的独立第三方产品和各活动模板的全部数据分支不在本次实访结果内。

本轮走查至可见的查询、录入和提交前状态。已验证一个字段的失焦错误，以及选择项带来的字段变化。服务端保存结果、取消后的脏数据策略、并发冲突、上传后的处理结果、屏幕阅读器、完整键盘路径和窄屏重排都待验证。参考图中的淡色提示、表头图标和多级页签，在 ERP 样页里应另测对比度、键盘焦点与可访问名称。
