# 基座归纳统一方案

日期：2026-11-24　状态：第 1 步止血、第 2 步规则、第 3 步护栏已做（2026-11-25；CI 用户定先只在本地跑）；第 4 步起暂停，用户 2026-11-25 定先等 YonBIP 操作流程走查清楚，再决定项目形态，样页不急。第 2 节描述的是止血前的情况

> 2026-11-25 用户定跟参照站：第 3 节 YonBIP 和样页两行、4.2、4.3 前三项、第 5 节的页面模式表已被取代，现行规则看 `docs/standards/`，取舍看 `2026-11-25-规范复核-按参照站.md`。

## 1. 结论

1. **乱的原因不是参照太多，是没有一份规则说了算。** 同一件事做了三遍，定下的规则留在会话里没落到文档，也没有工具拦。
2. **归纳办法**：每个参照只取一类东西（第 3 节）；两家以上一致的直接定，冲突的逐条裁决（第 4 节），只有一家有的等业务或等样页。
3. **收成**：一份规则（`AGENTS.md` + `docs/standards/`）、一套封装（`src/shared/ui`）、5 种页面模式。
4. **顺序是先止血、再立规则和护栏、最后收封装。** 护栏没立之前不再加新页面。

## 2. 乱在哪（实测）

| 现象 | 实测 |
|---|---|
| 同一件事做三遍 | 项目岗位两份（`features/project/role`、`features/positions`）加供应商样页：外壳 3 套、列表封装 3 种写法、状态样式 3 种、数据来源 3 种（接口 + MSW、localStorage、内存） |
| 表单逻辑各写一遍 | 三个录入表单都自己实现打开重置和保存锁；未保存提示、服务端字段错误只有两份有；冲突和幂等只有基座版有；聚焦首个错误、继续新增只有样页有 |
| 规则没落地 | 微盟采纳的 14 项、样页发现的 5 条只在会话和样页 `data.ts` 的 `ruleList` 里。方案文档自首次提交后没改过，仍写“工程未搭”、金额用 formatter/parser（试验三已否掉） |
| 过时结论被当成规则 | `独立报告/claude.md` 和 `CLAUDE.md` 在 Windows 上不分大小写，AI 一读这个目录就把它当项目规则自动载入，里面写的是 **React 19 + antd 6**。本次会话实际发生 |
| 演示页进了正式构建 | `vite.config.ts` 有一行未提交的改动把 `positions.html` 加进入口，`dist/` 里已有这份 localStorage 演示代码 |
| 规划与现状不符 | 方案点名的 `AGENTS.md`、`CLAUDE.md`、`docs/standards/`、ESLint、CI、生成器都没有；16 个封装有 8 个，其中 `DataTable` 现在叫 `ListTable`；`ConflictDialog` 不在清单里 |
| 主题两份 | `element-theme/` 和 `src/theme/` 目前只差一处注释，以后改一处就会分叉 |
| 会话共用目录 | 已发生一次误覆盖。写这份文档时，另一个会话正在改样页 |

**canteen 说明了不立护栏的结果**（同样是 Vue + Element Plus，53 个页面）：公共列表封装 `ResourceListPage` 被用 **0 次**，37 页直接写 `el-table`；未保存确认只有 1 页用，有弹窗的是 32 页；42 页直接用 `ElMessage` / `ElMessageBox`；硬编码颜色 432 处、79 种；弹窗宽度 13 种、操作列宽 13 种。封装写出来不等于会被用。

## 5. 统一后的结构

```text
AGENTS.md              规则入口；CLAUDE.md 只写 @AGENTS.md
docs/standards/        规则正文（4.1 已搬过去）
src/theme/             token 与动效，唯一一份
src/shared/ui/         组合封装
src/shared/patterns/   5 种页面模式
src/features/<域>/<资源>/  只写字段、规则、业务动作
```

| 页面模式 | 用在 | 骨架来自 | 现状 |
|---|---|---|---|
| 列表档案 | 供应商、银行账户、台账 | 微盟 + 样页 | 样页有，没进基座 |
| 树 + 列表 | 项目岗位、科目 | YonBIP | 基座版有，缺分类层 |
| 单据 | 付款申请、合同 | YonBIP + 方案 | 只有 `EditTable` |
| 参照弹层 | 组织、供应商、来源单 | 两家 | 样页 `OrgPicker` |
| 工作台与审批 | 待办、办理 | YonBIP 图 08 + 方案 | 首页占位 |

核销、对账、计划矩阵仍写专页，不进模式。

**封装怎么动**（沿用“两个真实页面有同一需求才扩展”）：

| 封装 | 动作 | 理由 |
|---|---|---|
| `FormDialog` | 新增 | 两个表单已各写一遍未保存、服务端错误、保存锁 |
| `DataTable` | `ListTable` 改名；加按类型的列、四种空态入口、行高、合计 | 方案已列为规范，两页都要 |
| `QueryBar` | 等 4.2 | 版式没定 |
| `StatusTag` | 样页改用它 | 现在有三套 |
| 列设置、跨页勾选、批量结果、参照、详情 | 先不抽 | 目前只有供应商一页用到 |
| 主题 | 补按钮 `font-family: inherit`、vxe 勾选色 | 样页发现，属于全局 |
