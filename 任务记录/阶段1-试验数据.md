# 阶段 1 试验数据

环境：Ryzen 7 5800H、31GB 内存、Windows 11、本机 Chrome（无界面模式）、视口 1366×768。
通过线是 2026-11-24 开工前经用户确认的。CPU 降速 4 倍用来模拟较旧的办公机。

页面：10 个字段的表单 + 200 行 × 15 列可编辑明细，8 个页签是同一个页面组件开的 8 张单据。

| 切换耗时（降速 4 倍，表单已填、表格已滚动，正式构建） | ≤ 200ms | 中位 784ms，最大 1209ms（n=12） | **不达标** |
| 切换耗时 P95（不降速，表单已填、表格已滚动，正式构建） | 没定 | 170ms（n=160，P50 93，最大 252） | 参考 |
| 切换耗时 P95（不降速，表格停在顶部，未压缩构建） | 没定 | 105.5ms（n=100） | 参考，不代表真实场景 |
| 切换后状态（表单、页面滚动、表格滚动、明细改动） | 全部保住 | 160 次零丢失 | 通过 |

切换慢是**未关闭的已知问题**。采样（不降速，每次切换）：样式重算约 31ms，布局约 9ms，脚本里最大的是强制布局 17.5ms。每张单据约 2500 个 DOM 节点，切换时整棵移出、移回文档；vxe-table 在 `onActivated` 里会 `recalculate()` 再 `refreshScroll()`。没有做拆分实验，不能断定主因。

局限：无界面 Chrome 的绘制可能比真机慢；160 次那组开头几秒与单元测试重叠，可能略偏慢；WeakRef 存活数未做反向验证，不作为依据。

## 试验二：200 行 EditTable（2026-11-24，**功能和精度通过**，耗时只记录）

200 行 × 15 列，8 列可编辑（文本、金额、数量、日期、下拉），正式构建。

| 项 | 通过线 | 实测 | 结论 |
|---|---|---|---|
| 全键盘连录 50 行（400 格） | 不丢焦点、值全对 | 丢焦点 0，错值 0 | 通过 |
| 连按不等待（快打字、扫码枪），175 格 × 两种速度 | 不丢键、不串格 | 不降速 0 错，降速 4 倍 0 错 | 通过（修复后） |
| 合计与 BigInt 独立算法 | 逐分一致 | 5 列全部一致，含 20 位整数、负数、空值 | 通过 |
| Esc 丢弃、Tab/Shift+Tab/Shift+Enter、只读列不可编辑、末格回车 | 正确 | 全部正确 | 通过 |
| 中文输入法组合输入 | 不跳格、文字正确 | 正确 | 通过 |
| 整表校验 + 点错误跳到对应格 | 5 处全对 | 5 处全对且聚焦；改正后再校验为空 | 通过 |
| 按键上屏 P95 | ≤ 100ms（4 倍） | 4 倍 46ms，不降速 10ms（n=114） | 达标 |
| Enter 到下一格 P95 | ≤ 200ms（4 倍） | 4 倍 **528ms**，不降速 55ms（n=133） | 4 倍**不达标**，按用户决定不优化 |
| 改金额到合计刷新 P95 | ≤ 200ms（4 倍） | 4 倍 **438ms**，不降速 44ms（只有 19 次，不足 100） | 4 倍**不达标**，样本不足 |
| 整表校验 | ≤ 500ms（4 倍） | 4 倍 P95 159ms（更早一次测得 558ms，超线），不降速 33ms（n=20） | 波动大，**不能算达标** |

局限：试验二、三运行时，我在同时写文件，同一目录里还有另一个会话在工作，耗时可能偏大；各项只跑了一到两次。

测试过程中发现并修掉的四处问题，都在我自己的封装里：

1. 编辑格挂载当拍就聚焦，el-input 收不到焦点事件 → 等一次 `nextTick` 再聚焦。
2. 日期格键入后弹层展开，Enter 被弹层吃掉 → 日期格的 Enter 一律确认并前进。
3. 下拉筛选后 Enter 选不中 → 加 `default-first-option`。
4. **连按时字会落到别的格**（175 格错 171 格）。vxe 的 `scrollTo` 要等 `setTimeout(30ms)` 才激活单元格，期间焦点在页面上。改为只触发滚动的同步部分再用 `isPos: false` 激活，全程在微任务里完成。`isPos` 在 4.24.4 源码里有、类型声明里没有，**升级 vxe 必须重跑 `trial2 E`**。

## 试验三：AmountInput（2026-11-24，**通过**）

| 项 | 通过线 | 实测 | 结论 |
|---|---|---|---|
| 键入 19 例（20 位整数、负数、零、前导零、全角、非法字符、限位） | 全过 | 0 失败 | 通过 |
| 粘贴 16 例（千分位、全角、括号负数、货币符号、换行；拒绝科学计数法、超小数位、超整数位、错位千分位、多格） | 全过 | 0 失败，拒绝时界面有原因提示 | 通过 |
| 光标 10 例（中间插入、退格、删除、非法字符、超位） | 不跳 | 0 失败 | 通过 |
| 1000 组随机值界面往返 | 零误差 | 0 误差 | 通过 |
| 核心算法与 BigInt 比对（1000 往返、500 组 200 行合计、500 次乘法） | 一致 | 全部一致（Vitest 56 项） | 通过 |
| 按键 P95 | ≤ 100ms（4 倍） | 4 倍 43ms，不降速 10ms（n=120） | 达标 |

**与方案的一处不同**：方案第 3 节写的是 `el-input` 的 formatter/parser 边输边加千分位。对照组实测：在逗号后按退格，删不掉数字且光标跳到末尾（`1,234,567@2` 退格 → `1,234,567@9`）。所以改为：聚焦显示纯数字、失焦显示千分位，仍是 `el-input` + 字符串 + decimal.js。

两条行为选择：科学计数法一律拒绝（Excel 显示 1.23E+10 时可能已丢位数）；超出小数位的非零数字不静默舍入，直接拒绝。
