# 六条流程走查总结 · A 段

**这六条流程已经查到当前身份能到的只读终点。没有一张存量单能连接来源、审批、下游和办结。** 实施时可以先沿用已核实的入口、查询、参照、计数和返回方式。后端状态转换、审批权限、引用范围及余额回写，仍需按流程分别验收。

| 流程 | 读到了哪里 | 阻点或证据边界 |
| --- | --- | --- |
| [F1 请假](F1-请假申请.md) | 五年个人申请、全时间待办／已办、我发起的全部与分状态 | 当前用户缺有效任职；没有审批样单。 |
| [F2 付款](F2-付款.md) | 应付单、付款申请、审批、计划编制、付款单 | 已核验日期和组织，当前可见范围没有同一张可串联样单。 |
| [F3 应收核销](F3-应收核销.md) | 核销汇总／明细；不限日期同币种和异币种查询 | 没有处理编号，无法核对分配金额、余额和冲销后果。 |
| [F4 资产借还](F4-资产借用到归还.md) | 申请、处理、借用单、归还单、台账 | 必填资产组织候选为零；查询止于校验，不能判定库中有无存量。 |

## 清单第 8 节逐项回答

**1．页面有几种，从进到出有几步？**  
现场能区分普通档案列表、树＋列表、列表与单据卡片、参照选单、审批／个人跟踪、双边匹配、报表台账等工作方式。“五种”可以是组件归类，同一个计数不能概括每条业务。以业务动作计，忽略打字和等待：岗位已在页内时，选分类 → 增行 → 取消是 3 步；组织参照的打开 → 勾选 → 确认是 3 步，执行列表查询再加 1 步；核销结果的打开条件 → 调范围 → 查询 → 切明细是 4 步。保存至办结的完整步数未知。建议基座沿用已有五种模式，给核销、对账和复杂报表预留独立工作区。依据：F6-02、F6-11～13、F6-16；F3-02～04；F1-03～08。

**2．编辑和浏览是否在同一页？**  
岗位从浏览切为表格行内草稿，取消后仍在原分类。请假、应收自制和资产借用的既有录入截图则显示完整表单或卡片。A 段没有保存后的实例，无法确认每种单据保存后留在编辑、切浏览还是返回列表。建议列表、草稿、浏览和办理分别定义可操作状态；需要多表体的单据保留充足的卡片空间。依据：F6-16；F1-01、F1-02；F2-01；F4-01、F4-04。

**3．状态怎样拆，动作由什么决定？**  
合同登记同时列出单据状态和合同状态；审批中心有自己的处理状态，个人跟踪又分运行中、已完成、已挂起。付款申请的“待生成”表达下游办理阶段。部分发放、部分核销等行状态缺实例。建议数据模型区分单据、审批、业务和行四个维度；每页按相关维度展示，动作由角色、所选记录和服务端能力共同决定。依据：F1-03～08；F2-03、F2-05；F5-01、F5-09。

**4．每个状态可做什么，禁用时给不给原因？**  
有证据的是空选和草稿态。投资类即使 0 行也能增行；集团供应商未选记录时分配置灰；核销汇总空选时撤销、联查凭证置灰。各按钮多无专属解释，而查询缺必输项会提示。建议区分“未选记录”“缺组织”“当前状态不允许”“无权限”，把用户可修复的原因放在相应控件旁。审批中、生效后、已办结的完整动作表尚不能定稿。依据：F6-02、F6-07、F6-09、F6-16；F3-01、F3-04；F4-04。

**5．拉单还是推单？能否多选、部分生成和回写？**  
付款申请和计划编制都有从下游挑选上游单据的入口；资产借用申请处理另有从选中的来源行生成借用单的入口。计划和资产处理页分别统计单数与行数。一次能选几单、拆并逻辑、部分生成后何时释放或占用余额，本次没有生成记录可查。建议保留“查看已选”、来源单号与来源行、原额与剩余额；在有样单时用同一来源分两次生成核对。依据：F2-03、F2-05；F4-05、F4-06。[付款申请选上游](../全量走查/流程截图/0068-付款申请-选择上游余额.jpg) · [计划选择申请](../全量走查/流程截图/0025-计划编制-选择付款申请.jpg)

**6．审批在哪办，能改什么，退回给谁？**  
工作台可进审批中心，从未处理或已处理队列找任务；“我的流程中心”适合跟踪本人发起、交办、监控、跟踪的流程。真正的审批页字段、必填意见、退回对象、办完去向均未看到。建议保留办理与跟踪两个入口，把可改金额和可退节点作为每个审批节点的契约，暂不统一假定。依据：F1-03～11；F2-04。

**7．核销怎样布局，撤销从哪里进？**  
既有核销工作区把本方与对方上下排列，各有已选数、余额和本次结算；查询条件也区分两方。本轮在结果查询确实看到了汇总和明细，以及“取消核销”；“删除核销记录”见于汇总。目录还有“取消核销并红冲”。三者入口不同，实际账务结果未执行。建议如首期含核销，采用独立工作区，保留本方／对方顺序和明确的金额口径；首期范围仍由业务清单决定。依据：F3-01～04、F3-09～10。[核销工作区](../全量走查/流程截图/0004-应收核销-工作区.jpg)

**8．生效后的单据怎样纠正？**  
收款合同列表有调整合同状态入口，补充协议有独立单据入口；结果查询中的红冲／取消属于另一条业务线。《项目管理》5.9.3（PDF 物理第 41 页）说明一份收款合同可关联多份补充协议，补充金额回写合同，支持历史版本对比。该依据不能证明演示环境中谁能直接修改、何时能终止，或某笔具体金额已回写。建议变更、终止、作废、红冲保留业务各自的用词、适用状态和联查对象。依据：F5-01、F5-05、F5-09～10；F3-01、F3-04。

**9．组织在哪里选，切换影响什么？**  
岗位在页头选项目组织，再选分类。付款单据和合同台账把组织放在查询区；请假按当前个人身份查询，未提供同样的组织切换。必填组织无候选会拦住查询，不能把当时的 0 条当作成功的空结果。建议顶栏可给默认上下文，每个业务页仍明确显示实际组织类型和范围。切换后对已选来源行或草稿的影响待样单验证。依据：F6-01～08；F1-01～02；F2-02、F2-08～09；F4-02～04；F5-02～06。

**10．档案归属和录入方式如何定？**  
项目岗位按组织范围和项目分类维护，父、子分类均可维护；录入采用行内增行。产品说明确认分类没有岗位时可向父级查找，已引用岗位不能删除，要求启用的经理岗位唯一。没有充分证据把唯一性扩大到整个公司，亦未证明不同分类能否同名。供应商有集团与业务单元两个入口，均能看到分配动作；分配后组织能改什么尚未知。建议先确定归属、继承与权限，再确定字段校验和编辑器。依据：F6-01～05、F6-09～18。

**11．查询区、状态页签、批量动作、列设置和详情怎样放？**  
供应商先选范围再查，付款申请用待提交／待生成／全部筛选；核销结果的汇总／明细切换改变可见动作。来源选择区同时显示单数与行数。此前已从供应商表头最右端打开列设置。空列表不能验证点行、双击或返回原行的统一规则。建议样页沿用这些位置，状态页签仅在能表达业务阶段时使用，详情位置由连续查看多条记录的任务决定。依据：F6-09～15；F2-03、F2-05；F3-01、F3-04。[供应商表格设置](../全量走查/流程截图/0057-供应商-集团-表格设置.jpg)

**12．与现有八条规则有什么一致或冲突？**  
以下是针对现行规范的核对意见，本轮未改规范。依据：[列表规则](../../../docs/standards/list.md) · [单据规则](../../../docs/standards/document.md)。

| 要复核的规则 | 现场与建议 | 步骤 |
| --- | --- | --- |
| 标题与主动作 | 单据列表和档案页都有明显操作区；岗位增行位于右表工具栏，随分类出现。“新增”位置应允许随维护对象变化。 | F6-01～02、F2-01 |
| 底部 | 大列表有已选和分页，来源选择还需区分单数／行数。岗位计数靠近右表标题。按任务选择计数位置。 | F2-05、F4-05～06、F6-02 |
| 单据动作 | 已看到保存、保存提交等独立入口；空表不证明提交后的副作用。固定操作区可保留，金额预占须由接口确认。 | F1-01、F2-01～05 |
| 表头 | 项目／财务／资产组织分别约束数据。多列表头有实例，切组织后哪些行作废未验证。 | F4-01～04、F5-01～03、F6-06 |
| 明细区 | 记录数、已选数、行操作在工作区内较易核对；并非所有表体都已验证全屏或键盘连续录入。 | F4-05～06、F6-02、F6-16 |
| 明细禁用 | 空组织或空选可禁用动作，站点有时仅给通用必输提示。保留本项目“说明还缺什么”的可用性改进。 | F4-04、F4-06、F6-07 |
| 树＋列表 | 投资类有子分类也能增行。节点是否可维护应按业务能力判断，不能仅据叶子／非叶子决定。 | F6-02～05、F6-17 |
| 参照弹层 | 搜索、显示停用、包含下级、已选数随参照类型变化。供应商能选全局＋集团；跨页保留和右侧已选面板没有普遍证据。 | F2-02、F2-08；F3-08；F6-11～15 |

**验收边界。** 本次可用于定稿的是入口、筛选范围、读写前的动作条件和若干文档明确的档案规则。审批流转、部分生成、核销后余额及角色级权限仍应留在验收清单中。后续有授权样单时，用同一单号贯穿前后两端，分别记录原值、操作、结果、余额和可继续办理的角色。
