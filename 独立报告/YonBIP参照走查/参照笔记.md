## 项目岗位，从进入到退出

| 操作 | 观察到的变化 | 对设计的意义 |
| --- | --- | --- |
| 在工作台的应用搜索输入“项目岗位”，点击命中项 | 新页签显示模块名，面包屑给出“项目管理 → 基础设置 → 项目人员 → 项目岗位” | 已知名称时可以直接进入，打开后仍能看见入口在业务目录中的位置。[图 09](截图/09-应用搜索项目岗位.jpg) · [图 10](截图/10-项目岗位初始态.jpg) |
| 进入页面，选中分类根节点 | 页头可见项目组织和“显示停用岗位”。右表保留列名、岗位数、已选数和空态 | 组织、分类和表格勾选是三个独立条件。根节点选中不能单独作为允许新增的依据。[图 10](截图/10-项目岗位初始态.jpg) · [图 11](截图/11-项目岗位分类根节点.jpg) |
| 选中“IPM 投资类”，再展开下级 | 岗位仍是 0 条，工具栏出现增行、修改、删除等动作，删除置灰。投资类本身有固定资产、股权、其他投资三个下级 | 父分类也能增行。若接入业务数据，需明确哪些节点允许维护，单看节点有没有子项会判断错误。[图 12](截图/12-项目岗位投资类工具栏.jpg) · [图 15](截图/15-项目岗位三级分类.jpg) |
| 在投资类下点“增行” | 岗位数从 0 变为 1，已选数仍为 0。编码单元格进入输入态，经理标记默认为否，启用状态默认为是。工具栏出现保存和取消，草稿行有“删行” | 草稿数、已选数和已保存数据要分别处理。必填列在编辑时可见。[图 13](截图/13-项目岗位增行草稿.jpg) |
| 取消这条未填写的岗位草稿 | 行数回到 0，仍选中投资类，常规工具栏恢复 | 可以把这条路径写成回归验收，连同分类和计数一起检查。[图 14](截图/14-项目岗位取消后.jpg) |
| 打开页头的组织选择器 | 项目组织弹窗显示搜索框、“显示停用”、组织树和确定／取消 | 对象多且有层级时，组织参照可以独立容纳查找和浏览。此次仅打开后取消，跨组织切换的效果待验证。[图 16](截图/16-项目组织参照选择器.jpg) |

## 和 Claude 讨论时要定的三件事

1. **岗位归属在哪一层？** 当前原型左侧按全部、经理、已停用分组，顶部显示“演示组织”。参照页可以选择项目组织和项目分类。请先用一条真实业务样例回答“同一组织的两个项目分类能否使用不同岗位”，再决定数据模型、左侧导航和新增入口。当前原型还有组织内经理岗唯一校验，参照截图只能证明存在经理标记，唯一性需要业务方确认。本地列表（独立版，已归档到 `archive/positions` 分支） · [图 12](截图/12-项目岗位投资类工具栏.jpg) · [图 16](截图/16-项目组织参照选择器.jpg)
2. **岗位维护的典型任务是录一个，还是连续录一组？** 当前原型用弹窗逐条编辑。参照页把岗位编码、名称、经理标记、启用状态和备注放在同一行。建议拿相同的三条岗位做一轮对照，记录重复点击、编码出错时的定位，以及退出草稿后保留的上下文，再决定是否启用已有的可编辑表格。本地编辑器（独立版，已归档到 `archive/positions` 分支） · [已有编辑表格](../../src/shared/ui/edit-table/EditTable.vue) · [图 13](截图/13-项目岗位增行草稿.jpg)
3. **哪些动作属于基座，哪些由业务页决定？** 建议让共享表格负责焦点、勾选、草稿计数和操作区位置，由页面决定当前分类能否增行、哪些字段必填、何时需要取消确认、是否允许“保存提交”。可以用三条路径验收：空分类仍可增行；取消岗位草稿保留分类；退出申请单草稿触发确认。[图 12](截图/12-项目岗位投资类工具栏.jpg) · [图 14](截图/14-项目岗位取消后.jpg) · [图 20](截图/20-单据退出确认.jpg)
